# Go To Mars v1.0 测试报告

日期：2026-10-25（Asia/Shanghai）。

## 结果

- TypeScript 严格类型检查通过。
- Vite 生产构建通过。
- 40 项核心自动测试全部通过。
- 11 项 Playwright 浏览器端到端测试全部通过。
- 三章十关通过真实页面操作连续通关，没有调用完成任务或奖励作弊接口。
- 单文件生产版本在浏览器离线状态完成首关，无 HTTP/HTTPS 请求，无页面运行时异常。

## 测试环境

macOS、Node.js 26.8.2、npm 11.19.1，TypeScript + Vite，Playwright 使用本机 Google Chrome。桌面视口 1440×1000；窄屏视口 390×844。未执行 Safari、Firefox、真实手机设备或长期外部玩家测试。

## 核心测试覆盖

1. 每个主线参考设计能够完成自己的任务并产生遥测。
2. 火箭方程、负载增加后的 Δv 与推重比变化、燃料流量。
3. 质量和燃料非负，分级移除质量但不凭空增加燃料。
4. 圆轨道近远地点、无推力能量误差、纯径向亚轨道远地点。
5. 同一飞行采用不同帧分组后的数值一致性。
6. 推重比不足、推进剂不足、月面缺少着陆腿、回收缺少降落伞、巡航断电、再入过热。
7. 暂停和终态停止仿真，开伞包线限制，出发窗口影响。
8. 仿真不修改原蓝图；自动飞行程序参数生效，关闭自动分级后保留上面级。
9. 模拟不推进战役；正式任务首次／重复奖励；参考设计全战役经费可行性。
10. 所有工程挑战存在满足 125% 载荷与 95% 费用上限的解。
11. 重复参考任务仍有利润；不按玩家堆高的造价计算奖励。
12. 存档设计、事件、遥测、飞行状态与进度的格式校验；恢复时规范化任务元数据。

## 视觉检查

实际截图检查任务中心与设计车间；检查文字、列布局、Canvas 显示、主要按钮和窄屏横向溢出。截图保存在 `docs/screenshots/`。游戏使用本地嵌入字体与程序绘制画面，避免运行依赖外部图片和字体服务。

## 修复记录

测试期间修正了上升飞行切向坐标、圆化点火、探空回收关机、跨天体巡航后的超时、着陆减速、分级耗油计算、重复 change 造成撤销空操作、刷新恢复结算、存档结构验证与经济软锁问题。

## 结果边界

本报告验证功能与数值一致性，不能证明航天工程精度、全平台兼容性或长期游戏平衡。缩尺天体、解析转移预算、简化热模型和预设进入走廊均为本版本的明确设计选择。设计范围见 GAME_DESIGN.md，运行方式见 README.md。
